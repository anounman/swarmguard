# SwarmGuard

**An independent security layer for multi-agent LLM systems: per-task IAM roles, one signed gateway as the only door to tools, and a small trained decider that watches the event log.**

Benchmarked on [MultiAgentDojo](https://github.com/james-pete/multiagentdojo) against multi-CaMeL (*Can CaMeLs Talk?*, [arXiv 2610.05640](https://arxiv.org/abs/2610.05640)) on the same suites and, where budget allowed, the same models. Built in one weekend for the Apart Research **Swarm Alignment Hackathon** (Nov 7–9, 2026), tracks 4 (Multi-Agent Oversight & Control) and 3 (Strengthening Agent Infrastructure).

> Numbers: `results/results.md` (regenerated by the loop; every figure in the report comes from `results/metrics.json`). Report: `docs/REPORT.md`. Plan and decision log: `PLAN.md`, `PROGRESS.md`.

## The idea in one paragraph

Multi-CaMeL stops prompt injection in multi-agent systems but pays for it with roughly half the utility (GPT-4.1: 78.4 → 24.7 on MultiAgentDojo, as reported). SwarmGuard keeps the deterministic guarantees and buys the utility back with a learned layer. Every sub-agent runs as a plugin with a fresh context behind a signed, per-task role: which tools, which recipients, which paths, how much budget, for how long. A single gateway checks every tool call against that role in well under a millisecond. Data that came from tool output is tainted; tainted values heading into irreversible tools (send, pay, share) are either denied (STATIC) or handed to a small fine-tuned model that scores the last few events and returns allow / flag / attenuate / kill (ADAPTIVE). The agent stays free inside its box; the box is enforced in code, never by prompting.

## Architecture

```
Orchestrator ──delegate──▶ Role Designer ──Role ⊆ parent──▶ Gateway mints Ed25519-signed token
                                                                 │
     sub-agent LLM ──tool_calls──▶ GuardedToolsExecutor ──▶ Gateway.check():
                                   token ok? · tool ∈ role? · args vs deny/egress rules? · taint ≤ clearance?
                                   → decider risk 0–10 → ALLOW | FLAG | ATTENUATE (narrower token) | KILL
                                   denied call: removed from the trace + PermissionError returned to the model
     every event ──▶ append-only JSONL log ──▶ decider window (last 8 events) + training rows
```

Five layers (details in `ARCHITECTURE.md`): orchestrator → role designer (template + optional small model) → gateway `sg` (deterministic) → agents as sandboxed plugins → executors. Plus two learned pieces: the **decider** (4B QLoRA, served by Ollama, called only on irreversible calls) and an optional cloud **auditor** on flagged cases.

## Configurations benchmarked

| Config | What is on | Deterministic | Learned |
|---|---|---|---|
| `NONE` | vanilla MultiAgentDojo | – | – |
| `STATIC` | roles, signed tokens, deny patterns, egress allow-lists, taint rule | ✓ | – |
| `ADAPTIVE_RULES` | STATIC + regex/structural monitor → attenuate/kill | ✓ | – |
| `ADAPTIVE` | STATIC + trained decider on grey-band and sink calls | ✓ | ✓ |
| `ADAPTIVE_AUDIT` | ADAPTIVE + cloud auditor on the flagged band (optional) | ✓ | ✓ |

Metrics per config × model: attack success rate (ASR), utility with and without attack, utility retention vs `NONE`, denied-benign-call rate (false-positive proxy), kills, gateway latency p50/p95, tokens and dollars. Models: gpt-oss:120b (headline), gpt-oss:20b, deepseek-v4.1-flash, plus a gpt-4.1 anchor against the paper's headline row. External numbers are always tagged *reported, not replicated*.

## Quick start

```bash
uv sync --dev
cp .env.example .env          # provider keys; see budget.yaml for which providers are allowed
uv run pytest -q              # ~140 tests, no network
```

Smoke one task per suite, see the gate decision first, then run the full loop:

```bash
make dry-run                  # plan + budget-gate decision per cell, launches nothing
make smoke                    # 1 user task × 1 injection per suite on gpt-oss:20b
make loop                     # build → smoke → bench → metrics → compare → harvest → retrain
make report                   # fills docs/REPORT.md placeholders from results/metrics.json
```

One cell by hand:

```bash
uv run python bench/run.py --bench mad --config STATIC --model gpt-oss:120b --suite workspace --attack important_instructions --key A
```

Use the trained decider: `ollama create swarmguard-decider:v3 -f train/Modelfile` (tagged so versions sit side by side), then `export SG_DECIDER_HOST=http://<host>:11434/v1`. Without it, `ADAPTIVE` falls back to a cloud stand-in and says so in the logs. Decider versions: **v2** = Qwen3-4B-Instruct-2507 QLoRA on public AgentDojo + AgentDrift rows (task-disjoint); **v3** = QLoRA from `ninty-seven/StepGuard` on v2 + our own MultiAgentDojo windows + ≈600 teacher-synthesised marker-free rows, calibrated with a `risk_map` (`make calibrate`). Both are reported; StepGuard and NVIDIA injection rows are converted but held for v4.

## Using `sg` in your own harness

`sg` does not depend on MultiAgentDojo. The gateway is an in-process library; the executor subclass is the only glue:

```python
from sg.schema import GuardConfig
from sg.gateway import Gateway
from sg.guard import GuardedToolsExecutor

gw = Gateway(GuardConfig.ADAPTIVE, run_id="r1", monitor=my_monitor, log_path="events.jsonl")
agent_id, token, role = gw.spawn(parent_token=None, spec_name="email_agent", tool_names=[...], task=user_task)
decision = gw.check(token, "send_email", {"recipients": ["bob@corp.com"]}, task_text=user_task)
```

Replace your tool executor with `GuardedToolsExecutor(gw, token, task_text)` and every call passes through `check()`. The `sg` CLI (`sg token mint|verify`, `sg check`, `sg run -- <cmd>`) wraps the same gateway for shell agents; `docker/` shows it as the only door out of a sandbox.

## Providers and budget

Five OpenAI-compatible providers, each model pinned to one: Ollama Cloud (gpt-oss tiers), Command Code (deepseek-v4.1-flash, `moonshotai/Kimi-K3.1-Pro`), OpenRouter (gpt-4.1 anchor), Anthropic via its OpenAI-compat endpoint `https://api.anthropic.com/v1` (claude-sonnet-5-5 / claude-opus-5-5 strong-model anchor; `strict` ignored, no caching), and Adaption Labs (`https://api.prod.adaptionlabs.ai/api/v1`, hackathon credit; qwen3.5-397b, gemma-4-31b-it; 20 requests/min per key, so the lane runs at concurrency 3, and the gateway rejects the `name` field on tool messages, which `bench/mad_guard.py` strips for that host — PLAN C33/C34). Current state (Nov 8, 09:35 CET): decider v2 is served and calibrated (val F1 0.862), ADAPTIVE(v2) benchmarks are running, decider v3 (StepGuard base) is served and calibrated (val F1 0.899) and ADAPTIVE(v3) benchmarks run beside v2. A missing provider key makes the gate print `GATE REFUSE … rc 2`, so `bench/supervise.py <cells.txt>` simply waits for the key. `budget.yaml` is the law: caps, reserves, Command Code's $20/5 h and $50/7 d windows, allowed models. `bench/run.py --dry-run` prints the gate decision; spend is appended per run to `runs/mad/spend.jsonl` and summarised in `results/spend.json`. Keys are read from the environment first and from `~/.zshrc` as fallback.

## Honesty notes

- Every external number is marked *reported, not replicated*; comparisons are made only on the shared benchmark, and where the model differs we compare utility retention rather than absolute utility.
- One seed. The decider's training data is partly synthetic; v3 includes trajectories from the same task suites we benchmark on (different models; deepseek-v4.1-flash held out as `test_mad_ood`) and is reported separately from v2. The synth teacher is that same held-out model, so `test_mad_ood` is out-of-distribution in the agent, not in the teacher's style.
- The STATIC taint rule arms on injection markers; adaptive attackers are out of scope tonight (see Limitations and Dual-Use in the report).
- `runs/mad/NONE/gpt-4.1/` is a partial undefended gpt-4.1 baseline, reported as partial.
